Guided Runtime Contract

Describe your application's expected behaviour. Each run records which steps passed, violated a rule or could not be tested.

1. Confirm your application map

Complete Startup method, Local app URL and Health path above. Detect reads source declarations without starting your application. Confirm router prefixes and expected health status.

Discovered routes and their source will appear here.

For an API, a path alone does not describe an operation: POST /orders needs a request body. Add these operations in step 3.

Example includes two users, an admin and expected access/payment rules. It fits the multi-service lab, but review every rule before testing your own application. It is not a benchmark answer key.

2. Add test accounts

Give each identity an alias, such as user_a or admin. Configure how login returns a token or cookie, and a GET endpoint that proves the logged-in username.

Save the contract/project in step 5 before saving account credentials. Credentials go to your OS vault. Tokens stay in worker memory. OAuth/MFA requires a dedicated adapter.

3. Build workflows

Add steps in order. Capture a response field (for example id as order_id), then use {{ '{{order_id}}' }} in a later path or JSON body. Each workflow has its own variables.

A setup step prepares data. A security assertion describes a rule such as another user must get 403/404. Failed setup blocks dependent steps; it does not prove a vulnerability.

4. Set limits and data lifecycle

The runner removes only its own stack and volumes after the run. Each workflow should create independent data. Shared state is not reset between steps or workflows. Custom reset commands are not supported.

5. Validate, save and run

  1. Confirm discovered paths and your expected business rules.
  2. Validate the contract structure, then save the project.
  3. Return to Accounts and save each test username/password securely.
  4. Select your DAST engine and analysis settings, then Start review.

Validation checks configuration. The run verifies health and account identity before testing workflows.
