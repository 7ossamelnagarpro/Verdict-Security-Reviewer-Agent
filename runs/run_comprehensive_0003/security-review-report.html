7. Reflected server-side cross-site scripting in catalog_search endpoint

Problem

The catalog_search endpoint interpolates the user‑controlled query parameter q directly into an HTML response without any sanitisation or encoding. The SQL query also uses string interpolation, but the XSS risk stems from the returned HTML where <h1>Results for {q}</h1> and each product name are inserted verbatim. An attacker can supply a payload such as <script>alert(1)</script> in the q parameter, which will be reflected back to the client and executed in the browser context, confirming a reflected XSS vulnerability.

Impact

An attacker can execute arbitrary JavaScript in the victim's browser, leading to session hijacking, credential theft, defacement, or further malicious actions against users of the application.

Location

api/extra.py:145

Detected by

  • codeql-cli: py/reflective-xss

Evidence

  • Source excerpt shows return f"<h1>Results for {q}</h1>" + "".join(f"<p>{row['name']}</p>" for row in rows) where q is directly inserted into HTML response.

Limitations

  • The review is based solely on static code analysis; runtime behaviour such as content security policies or additional sanitisation layers are not observed.

Recommended fix

Properly encode user input before embedding it in HTML. Use a templating engine that auto‑escapes, or explicitly HTML‑escape q and any dynamic data. Additionally, employ parameterised queries for the SQL statement to prevent SQL injection. Example fix:
``python
from html import escape

@router.get("/catalog/search", response_class=HTMLResponse)
def catalog_search(q: str = ""):

with connection() as conn:
rows = conn.execute("SELECT name FROM products WHERE name ILIKE %s", (f"%{q}%",)).fetchall()
return f"<h1>Results for {safe_q}</h1>" + "".join(f"<p>{escape(row['name'])}</p>" for row in rows)
``
