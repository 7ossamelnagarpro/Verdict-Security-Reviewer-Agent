24Missing token type validation in refresh endpointai-399c790f8ce192d7mediumlikely vulnerabilitywarn⌄

Assessment

The /auth/refresh endpoint accepts any Authorization header, extracts a user via principal(), and issues a new access token without verifying that the supplied token is a refresh token or checking its revocation status. This pattern can allow an attacker who possesses a valid access token to repeatedly obtain fresh tokens, effectively extending the lifetime of a compromised credential.

Impact

An attacker with a stolen access token could call the refresh endpoint to receive new access tokens indefinitely, leading to prolonged unauthorized access, privilege escalation, and potential data exfiltration.

Remediation

Modify the refresh endpoint to: (1) require a token of type "refresh" (e.g., by checking a claim in the token payload); (2) verify the token against a revocation list or expiration check; (3) reject requests that present access tokens or revoked refresh tokens; and (4) consider rotating refresh tokens after each use.
