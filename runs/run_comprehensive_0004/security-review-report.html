Problem

Impact

Location

Detected by

  • codeql-cli: py/sql-injection

Evidence

  • The query string is executed directly via conn.execute(query) without sanitisation

Limitations

  • The review is based solely on static code analysis; runtime behaviour (e.g., input validation elsewhere) was not observed.

AND password = ?"; row = conn.execute(query, (body.username, body.password)).fetchone(). Additionally, consider hashing passwords and using secure authentication mechanisms.
